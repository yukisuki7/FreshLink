# 面向连锁餐饮的生鲜食材仓储与配送管理系统

## 启动与登录

课堂演示使用同一套 v2.1 前端、后端和数据库。D4 B 从已合并 D3 的 `main@1f2c837` 开发。最终演示前在同一工作副本记录 `git rev-parse HEAD`，并在验收记录填入前后端版本和实际测试库名。

1. 运行 MySQL 和 Redis。按[团队本机开发指南](团队本机开发指南.md)在项目根目录运行 `Setup-Team.ps1`，使用独立的 `freshlink_*` 测试库。新库用 `Initialize-TeamDatabase.ps1`，它会应用已有 D1～D3 迁移。演示例程只在隔离库操作。
2. 已有 D2 测试库先备份，依次执行 `apps/backend/db/fresh/D3_00_outbound.sql` 和 `D3_01_delivery.sql`，再确认两个迁移版本和既有库存余额。已迁移并包含 D3 单据的演示库直接复用。详情见[D3 接口与迁移说明](tasks/D3出库与配送接口合同.md)。
3. 首次从配置好的工作副本构建并安装依赖，然后分别打开两个 PowerShell 窗口启动前后端。课堂菜单默认关闭，按下方命令在前端构建和启动所在的窗口显式开启。

```powershell
pwsh -NoProfile -File .\scripts\team\Install-TeamFrontend.ps1
pwsh -NoProfile -File .\scripts\team\Build-TeamBackend.ps1
$env:VITE_FRESH_CLASSROOM_MODE = 'true'
pwsh -NoProfile -File .\scripts\team\Build-TeamFrontend.ps1
```

```powershell
# 一个终端运行后端
pwsh -NoProfile -File .\scripts\team\Start-TeamBackend.ps1
# 另一个终端运行前端
$env:VITE_FRESH_CLASSROOM_MODE = 'true'
pwsh -NoProfile -File .\scripts\team\Start-TeamFrontend.ps1
```

按 Setup 输出访问前端，默认是 `http://127.0.0.1:13102/`。演示主流程使用 `fresh_wh`，`fresh_hq` 查看总部授权，`fresh_store_a` 和 `fresh_store_b` 对照门店权限。账号密码仅使用本机初始化生成的版本，必要时在项目根目录以 Windows PowerShell 运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\team\Show-TeamDemoAccounts.ps1`。演示资料中只记录角色。

验证重启时记录出库单和配送单号，分别停止前后端并运行同样的启动命令。重登后查到原批次、结余和已送达记录。重启使用原数据库，不执行初始化脚本。

## 约 8 分钟演示

以 Asia/Shanghai 当日为 T。使用鸡胸肉 1kg/袋、冷藏、临期阈值 3 天。准备启用供应商、门店 A、同仓的收货暂存位 R1 和冷藏正式储位 C1。新建唯一批号 B1/B2，生产日期 T−2，到期分别是 T＋2 和 T＋8；计划数量 10 和 20 袋。同一份演示记录贯穿全程。

| 时段 | 操作与讲解 |
| --- | --- |
| 0:00–1:00 | 打开首页，说明角色与业务边界。核对食材、供应商、门店、仓区位的启用状态。 |
| 1:00–2:20 | 进入批次入库单，填供应商、食材、批号、生产/到期日和数量。按既有入库流程提交、审核，再创建收货任务。 |
| 2:20–3:30 | 到 R1 实际收货 10＋20 袋，查库存确认增加 30。将两批上架至 C1，核对 R1 减 30、C1 加 30，整体数量保持。 |
| 3:30–4:15 | 刷新「库存与效期」。核对来源、位置、B1 临期、B2 正常。展示到期当天的独立历史夹具，可出库量为 0 且有原因。预置反例只用于验证边界，正向数据由真实入库生成。 |
| 4:15–5:30 | 选门店 A 和 C1 的 B1，先输入 11 展示超量提示，改成 6 并保存草稿。草稿不占库存。确认出库后演示批次总量 30→24、B1 余 4、B2 仍 20，并生成一张待配送单。重复确认后的库存、配送单号保持一致。 |
| 5:30–7:00 | 查看关联配送，核对门店地址快照与批次数量。保存配送资料、开始配送、确认送达，库存仍为 24。已送达表示仓管登记的物流状态。 |
| 7:00–8:00 | 在库存页按批次追溯出库记录。门店 A 从「我的门店与配送」查看本店信息，门店 B 看不到 A 的配送。说明重启后可以重新查询同一单据。 |

演练前记录所选批次的基线，现有隔离库可能带有其他批次。按本次两批对账；需要展示食材全仓恰好 30→24 时，在新库完成正向入库后单独准备过期反例。

## 接口及范围

- 批次入库、收货、上架及库存效期使用 [D2 合同](tasks/D2入库与效期接口合同.md)。
- 出库、配送及权限使用 [D3 合同](tasks/D3出库与配送接口合同.md)。表单超量提示可在现场展示。库存不足的服务端反例可用后端探针复跑，核对整单库存、流水、状态和配送单均无部分变化。
- 演示范围包括基础资料、入库、库存效期、人工选批与配送。AI、门店申领审批、自动 FEFO、波次拣货、复杂签收和退货留在本次范围之外。
- 构建、测试、截图、重启验证和未复验项按 [D4 验收标准](../specs/生鲜课设改造/validation.md#d4-演示收口)记录，最终由负责人独立验收。
