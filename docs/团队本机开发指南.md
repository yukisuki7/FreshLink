# FreshLink 团队本机开发指南

FreshLink 是一个面向生鲜仓储管理的课程项目，基于 JeecgBoot 后端（Java 17、Spring Boot、MySQL、Redis）和 Vue/Vite 前端。团队仓库包含前后端、P1 基线以及v2.1 的 D1/D2/D3/D4 课堂演示任务规格。每位同学在自己的电脑克隆仓库、创建独立本地数据库与账号后开发，通过 Git 分支提交小步改动供负责人审查。

## 1. 准备本机环境

需要 Windows、PowerShell 7、JDK 17、Maven、Node.js 20.18.1 或更高版本、pnpm 11.25.0、MySQL 命令行客户端、MySQL 服务和 Redis 服务。锁文件记录了经项目确认的包管理器版本；如本机版本不同，先按仓库 `package.json` 的 `packageManager` 字段安装对应版本。Setup 会检查工具版本、MySQL/Redis 端口连通性以及前后端端口空闲情况；它不会安装工具、启动/停止服务或修改数据库。按本机安装位置传入工具路径即可，不要求固定盘符。

从 GitHub 克隆后，在仓库根目录打开 PowerShell：

```powershell
pwsh -NoProfile -File .\scripts\team\Setup-Team.ps1
```

脚本会要求输入一个全新的 `freshlink_*` schema 名称和本机 MySQL 应用账号及密码。由数据库初始化脚本用单独输入的 DBA 凭据创建新 schema 和缺失的本机应用账号，并仅授予该新 schema 权限；如果该应用账号已存在，初始化会检查其密码及权限范围，不会改写已有账号。Setup 不会创建账号、授予权限或改数据库。MySQL/Redis 主机与端口、后端端口（默认 18081）、前端端口（默认 13102）均可通过参数调整。可用 `Get-Help .\scripts\team\Setup-Team.ps1 -Full` 查看参数。

连接配置写入 `runtime/config/team-private.json`，密码使用当前 Windows 用户的 DPAPI 加密并设置本机 ACL。配置不能复制到其他 Windows 用户或电脑；每位同学必须分别 Setup。不要把该文件、`runtime/config/team-demo-accounts.json`、`.env.development.local`、日志或任何本机密码提交到 Git。前端签名值是源码约定的公开演示常量；不要把数据库/Redis 密码写入前端环境文件。

## 2. 初始化独立开发数据库

先确保 MySQL 与 Redis 已由本机服务管理工具启动。数据库初始化只允许使用新的空 `freshlink_*` schema，绝不选择原课程库或其他已有数据 schema。应用账号只需有该新 schema 的读写/建表权限；初始化脚本会另外要求 DBA 账号以 SecureString 交互输入，用于创建缺失 schema/本机应用账号并导入基线。DBA 凭据不会保存。

仓库已提供 `scripts/team/Initialize-TeamDatabase.ps1` 和 `apps/backend/db/team/00_base_schema.sql`、`01_framework_seed.sql` 后运行：

```powershell
pwsh -NoProfile -File .\scripts\team\Initialize-TeamDatabase.ps1
```

初始化脚本先导入 `apps/backend/db/team/` 的 `00_base_schema.sql` 和 `01_framework_seed.sql`，再依次导入 `apps/backend/db/fresh/` 下的增量：

1. `P1_00_schema.sql`、`P1_10_menu_role_dict.sql`、`P1_20_demo_data.sql`
2. `D1_00_warehouse_codes.sql`
3. `D2_00_inbound_lots.sql`
4. `D3_00_outbound.sql`、`D3_01_delivery.sql`

最后生成本机演示账号。账号密码每机随机生成，写入被 Git 忽略且 ACL 保护的 `runtime/config/team-demo-accounts.json`。初始化脚本只接受尚不存在的新 schema。

保留已有的 D2 独立开发库时，先备份并确认当前连接的库名，再按上述顺序仅补两份 D3 SQL。已有 D3 库可查询 `fresh_schema_migration`，确认存在 `D3.00` 和 `D3.01`，然后启动新构建的后端。后端启动时不会自动补跑迁移。

## 3. 安装依赖与构建

前端依赖按仓库锁文件安装，缓存留在项目 `runtime/cache`：

```powershell
pwsh -NoProfile -File .\scripts\team\Install-TeamFrontend.ps1
pwsh -NoProfile -File .\scripts\team\Build-TeamBackend.ps1
pwsh -NoProfile -File .\scripts\team\Build-TeamFrontend.ps1
```

后端首次 Maven 构建会从仓库下载依赖到项目内 `runtime/cache/maven-repository`。构建脚本不会自动运行测试；后端 POM 默认跳过测试。不要用旧 `scripts/Build*.ps1` 或 `scripts/Start*.ps1` 作为团队入口，它们是原开发机脚本，包含机器专属路径与本机配置。

## 4. 启动服务

在两个 PowerShell 窗口分别启动，窗口保持打开；按 Ctrl+C 停止对应服务：

```powershell
pwsh -NoProfile -File .\scripts\team\Start-TeamBackend.ps1
pwsh -NoProfile -File .\scripts\team\Start-TeamFrontend.ps1
```

前端默认地址为 `http://127.0.0.1:13102/`，后端 API 为 `http://127.0.0.1:18081/jeecg-boot`。脚本只监听本机回环地址，只启动当前仓库构建出的后端包和 Vite，不会以隐藏窗口启动其他进程。数据库由前述 SQL 脚本管理，所以运行时关闭 Flyway 自动迁移；Quartz 定时任务也默认关闭。先完成数据库初始化和构建；AI 模型密钥不是基础业务流程的启动条件，未配置时 AI 功能不可用。

## 5. 测试与提交审查

仅运行仓库标记为 fresh 白名单的测试：

```powershell
pwsh -NoProfile -File .\scripts\team\Test-Team.ps1 -EvidenceDirectory .\work\test-evidence\D2-YYYYMMDD
```

测试证据必须放在 `work/` 下，每次用一个尚不存在的新目录；脚本保存 Maven 与前端测试日志及 `results.md`，并在摘要中注明测试数（若日志格式无法解析，查看原始日志）。这不是全仓完整测试或人工 UI 验收。每完成一个可独立审查的任务片段（例如 D2 的批次入库），先整理改动与测试证据、提交到个人分支，再发给负责人审查；不要把多个无关任务攒成一个提交，也不要直接推送主分支。

## 脚本说明

团队入口位于 `scripts/team/`，采用仓库相对路径与本机私有配置。根目录 `scripts/` 中的既有脚本是旧开发环境专用，不作为新克隆流程的依据。
